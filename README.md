# Aarre

Aarre 是一个 Chrome 原生书签增强层。它把标题、URL 和文件夹写入真实的 Chrome 书签，并在本地保存网页摘要、标签等智能信息。自建云端服务、腾讯云私有 COS/CAM、Google Web OAuth、加密数据库备份、两分钟健康巡检、独立 GlitchTip 错误项目与恢复材料已经上线；`sync.nexvoice.cc` 的 DNS、公开 TLS、隐私/条款页面和真实 Google OAuth 登录链路均已通过。真实账号已完成 262 条资源及其收藏位置、设置和用量 metadata 的首次同步；当前 Google 品牌仍在审核，完整图片备份、卸载重装恢复和正式 Web Store ID 仍待验收，本地功能不受这些外部门槛影响。

## 已实现的关键闭环

- 侧边栏默认直接展示当前 Chrome 配置文件的原生书签栏及完整文件夹树。
- 同时覆盖账号书签栏、本机书签栏、其他书签和移动设备书签，避免遗漏 Chrome 星标保存到非默认目录的内容。
- 新增、改名、移动、拖放和删除操作直接写入 `chrome.bookmarks`，界面监听原生变更并实时刷新。
- 当前网页的右键菜单会持续跟随活动标签的真实 Chrome 收藏状态：未收藏时显示“添加到收藏…”，已收藏时显示“管理此收藏…”。Chrome 不提供右键菜单显示前的链接目标回调，因此链接项使用诚实的中性文案“添加或管理此链接…”，点击后再校验。完全相同的记录直接更新；规范化相同或存在多条记录时必须由用户明确选择，不会静默合并或制造重复收藏。
- 顶部统一输入框可搜索书签、浏览历史和已打开标签页，也可输入网址直达或调用 Chrome 当前默认搜索引擎。
- 使用 Chrome 侧边栏按需分析和收藏当前页面。
- 提取正文、描述、作者、站点、Canonical URL、图片和用户选中文字。
- 用户可编辑收藏名称、收藏原因和原生 Chrome 文件夹。
- 保存时创建或更新真实 Chrome 原生书签，并把 AI 摘要、标签和真实页面截图作为同一条完整增强任务处理。
- 监听原生书签的新增、改名、移动和删除；即使用户使用 Chrome 自带星标，新增记录也会自动进入 Aarre 的摘要、标签和截图增强队列。
- 无需云端账号即可完整使用本地保存、检索、摘要、标签和 Agent。
- 旧版 Supabase 路径已删除；可选云端改为自建 Fastify/PostgreSQL 服务和腾讯云私有 COS，并保持用户显式开启、失败关闭。
- 支持扩展使用用户提供的 API Key 直接调用 Gemini、OpenAI、DeepSeek，生成中文摘要、标签和主题；三家服务均要求配置自己的 Key，处理发生在所选 AI 服务商，不经过 Aarre 自己的服务器。
- 设置页提供显式启动的全目录 AI 扫描：在用户授权网页读取权限后，逐条提取网页描述、标题、首段与路径信息，补全旧书签的简介、标签和主题；任务可暂停、恢复和取消。
- 收藏列表直接展示名称、AI 简介、标签和完整 URL；尚未扫描的项目会明确显示待处理状态。
- 网页端收藏库使用单行极简顶部，搜索框只搜索收藏标题、标签、摘要和文件夹；可按真实 Chrome 文件夹及“全部/已理解/待处理”筛选，并按 Chrome 顺序、最近/最早收藏、最近使用、最近更新或标题排序，查询与控制状态写入 URL，刷新后保持。
- 每张瀑布流卡片都可编辑对应 Chrome 收藏的名称、网址和文件夹，以及 Aarre 的自定义标签和备注；同一网站存在多个收藏位置时先明确选择，删除只作用于所选位置并保留 30 天恢复记录。
- 收藏库大封面只使用真实网页截图；没有可信截图时，从随扩展打包的 40 张 Aarre 兜底封面中按语义或 canonical URL 稳定分配，不使用侧边栏分类图、普通 `og:image` 或低清站点图标冒充网页截图。
- 底部 Agent 使用全目录紧凑索引和最近会话上下文回答，不再只截取少量关键词结果；发送后进入独立会话页，真实历史会话保存在当前 Chrome 配置中。
- 本地检索覆盖标题、摘要、标签、AI 别名、中文二元组和拼音，不依赖云端语义检索。
- 现有 Chrome 书签自动进入本地智能索引，无需手动导入。已收藏且缺少截图的网页无论从 Aarre、地址栏还是普通链接打开，都会在页面加载完成、字体和首屏图片就绪、DOM 短暂稳定后自动补拍；从 Aarre 打开或正常浏览补齐旧图成功时，网页底部提示“封面截图已更新”，Chrome 星标和 Aarre 新收藏的首次截图保持静默。已有截图只在距上次采集满 7 天后随正常浏览静默刷新，不会每次访问都重拍。
- 存量缺图收藏可在收藏库中显式启动「补齐缺失封面」：Aarre 复用一个不抢焦点的后台专用标签页，通过 `chrome.debugger` 逐页加载并截图；开始后可以正常使用 Chrome，任务支持暂停、继续和取消。该任务只生成本机截图，不调用 AI、不上传图片；安全验证页（如 Cloudflare 挑战）会被识别并快速跳过，不会长期占住队列。
- 原生书签始终以 Chrome 为唯一事实来源，智能层不会用云端副本覆盖 Chrome 的标题、URL 或文件夹结构。

## 数据边界

| 数据 | 真实来源 | 同步方式 |
| --- | --- | --- |
| 标题、URL、文件夹 | Chrome 原生书签 | Chrome Sync |
| 收藏原因、摘要、标签 | Aarre | 默认本地；用户明确连接后可加密同步到 Aarre 云端 |
| 页面截图 | Aarre | 默认本地；只有用户选择“完整云端备份”后才加密上传腾讯云私有 COS |
| Agent 历史会话 | Aarre | 默认本地；用户开启云端后同步稳定消息，不上传运行中 progress |
| AI 模型密钥 | 当前 Chrome 配置文件 | 由扩展直接发送给用户选择的 AI 服务商 |
| 待同步内容 | 当前 Chrome 配置文件本地 | 云端关闭/断网时保留在持久 Outbox，恢复后幂等补同步 |

统一输入框只在用户输入时查询 Chrome History API 生成本机联想，不会把完整浏览历史写入产品数据库。Chrome 星标和 Aarre 保存都固定创建完整增强任务，不再提供容易造成半成品的 AI 勾选项。权限、AI Key、网络或合适的前台页面暂不可用时，原生书签照常保存，AI 与截图任务持久等待，并在配置恢复或该收藏下次以任意正常方式打开后继续。无痕、内部、局域网、银行、支付、医疗、用户排除页面和受保护文件夹不读取正文、不发送给 AI、也不截图或上传。网页正文、Cookie、完整浏览历史和 API Key 永不进入 Aarre 云端。

## 本地开发

要求 Node.js 22 或更高版本。

```bash
nvm use
npm ci
npm run check
```

生产构建输出在 `dist/`。在 `chrome://extensions` 打开开发者模式，选择“加载已解压的扩展程序”，然后选择 `dist/`。

## 云端同步状态：生产服务已上线，等待安装态恢复验收

旧版 Supabase Auth、Postgres RLS、Edge Function 和云端 AI 路径已经删除。当前代码使用 Google Web OAuth broker + 一次性 PKCE ticket、自建 Fastify API、独立 PostgreSQL database、逐用户 AES-GCM 信封加密和腾讯云私有 COS。

同步边界固定为：

- “仅文字与设置”同步摘要、标签、主题、备注、设置、会话、报告和恢复信息，不上传图片二进制。
- “完整云端备份”在上述范围外加密上传页面快照、封面与站点标识；必须由用户主动选择。
- 受保护资源不上传，并会触发服务端删除既有元数据和 COS 全部对象版本。
- 备注/用户标签的并发修改保留两份冲突版本，侧边栏和网页端可选择或合并，不静默覆盖。
- 页面正文、Cookie、完整浏览历史、Chrome 原生 ID 和 API Key 永不上传。
- 用户的 Gemini、OpenAI 或 DeepSeek Key 只保存在当前 Chrome 配置中，由扩展直接调用所选服务商，不经过 Aarre 服务器。
- Chrome 标题、URL 和文件夹结构继续以 Chrome 原生书签为唯一事实来源。

普通构建不会默认连接生产 API；生产构建必须显式设置 `AARRE_CLOUD_RELEASE=1` 与 `VITE_AARRE_API_BASE_URL=https://...`。当前 `dist/` 已按 `https://sync.nexvoice.cc` 生成 cloud-enabled 0.5.33 构建。服务端 0.1.9 接纳客户端真实用量字段、保持未知字段严格拒绝，并把首次同步改为遵守 `Retry-After` 的后台分批续传；显式选择的同步范围会先写云端，旧设备不能在同一次操作里把“完整备份”覆盖回“文字与设置”。COS/CAM、SSE-COS AES-256、跨地域复制、全版本删除、PostgreSQL 隔离恢复、DNS/TLS、公开 OAuth、OAuth 日志脱敏、健康巡检和 GlitchTip 受控事件演练已通过；仍需完整图片备份、卸载重装恢复、Google 品牌审核、正式 Web Store Extension ID 和 50 个真实账号的并发压测。完整容量与腾讯云采购计划见 [docs/CLOUD_CAPACITY_PLAN.md](docs/CLOUD_CAPACITY_PLAN.md)。

生产账号、权限、加密恢复包、SSH 恢复、控制台入口、部署、回滚和故障排查统一从 [ops/README.md](ops/README.md) 进入。Git 只保存加密凭据包和校验值，恢复口令、控制台账号、MFA、Cookie 和用户 BYOK Key 永远留在 Git 外。

## 已知边界

- 扩展不能修改 Chrome 原生书签栏或原生星标弹窗。
- 扩展不能接管 Chrome 地址栏内部实现；当前覆盖书签、历史记录、已打开标签页、网址直达和默认搜索引擎，无法复制 Chrome 未公开的计算器、站点搜索快捷词等内部能力。
- 扩展不能替用户开启 Chrome Sync；它会优先显示 Chrome 标记为账号同步的书签栏，实际同步开关仍由 Chrome 设置控制。
- Chrome 内部页、Chrome Web Store 等受保护页面不能读取正文。
- 无痕、银行、支付、医疗、内网和用户排除的网站不会读取正文、调用 AI 或截图，统一使用 Aarre 兜底图；这是隐私边界，不会用伪造图片冒充网页截图。
- 普通浏览路径的自动补拍仍使用 `captureVisibleTab()`，只能截当前活动标签页；连续打开多个缺图网站后，先退到后台的页面不会在后台直接截图，它们会保留待办并在用户之后切回且页面稳定时自动补拍。需要一次处理存量缺图收藏时，使用收藏库里的「补齐缺失封面」后台任务；该任务通过 `chrome.debugger` 对后台专用标签页截图，不占用前台，Chrome 会显示一次“扩展正在调试此浏览器”提示。
- 旧书签会自动出现在侧边栏；配置 AI 后可在设置页启动全目录扫描。失效链接、登录墙和内部地址可能只能生成保守摘要，或被隐私规则跳过。
- Chrome 移动端不能运行扩展；原生书签仍可由 Chrome Sync 到手机，智能管理端后续需要 Web/PWA。
- 删除书签或文件夹前会写入本机撤销快照，删除后的结构保留 30 天，可在设置页「最近的更改」里恢复。

详细架构见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。
