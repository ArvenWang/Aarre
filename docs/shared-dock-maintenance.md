# 共享侧栏放在 NexAlign 仓库：可行性评估

2026-09-14，按用户最新方案修订。仅评估；本轮没有建立共享包、移动源码、修改依赖关系或接入发布流水线。

## 结论

可行，而且适合目前只有两个项目的规模。建议把共享组件放在 NexAlign 仓库的 `packages/suite-dock/`，作为有独立版本的包；NexAlign 和 Aarre 在构建时引用。无需第三个仓库，也无需合并两个应用。

每个插件的安装包都内置自己使用的组件代码。用户只安装 NexAlign、只安装 Aarre，或同时安装两者，都应有完整可用的侧栏；卸载其中一个不影响另一个。双安装时继续使用当前跨扩展握手合并入口，单安装时显示自己的入口。这是源码维护方式的变化，不改变用户的安装选择。

## 在现有项目中怎么接入

目前八个 `src/shared/suite-dock/` 模块已经一致，但有两份副本；它们是普通 TypeScript 与 DOM/CSS 实现，不依赖两个产品各自的 React 页面。可将这些模块、正式图标资产，以及两宿主中仍重复的外壳样式收拢进上述包。收藏、检查、鉴权与业务存储留在各自项目，宿主通过参数和回调连接共享外壳。

NexAlign 可以把这个目录声明为 npm workspace；Aarre 开发时以本地包路径引用它。npm 支持工作区内的子包和 `file:` 本地包依赖，能够实现修改 NexAlign 下的同一份源码后，两个构建读取同一份组件。[npm Workspaces](https://docs.npmjs.com/cli/v11/using-npm/workspaces/)、[本地包依赖](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#local-paths)

建议开发时与正式构建分开处理：

| 场景 | 建议方式 | 结果 |
| --- | --- | --- |
| 本机联调 | Aarre 引用 NexAlign 中的本地组件包 | 一处修改，两边重新构建即可看到 |
| CI / 发布 | 将该目录打成带版本的包，两项目锁定同一版本 | 可复现构建，可单独回滚，不依赖开发者磁盘目录 |
| 用户安装 | 两份扩展分别包含组件代码 | 单安装、双安装、离线使用均不依赖另一插件存在 |

正式包可以用 npm 包或版本固定的 `.tgz`；npm 本身支持把子目录中的包打包，并通过包文件或 URL 安装。因此组件源码仍归 NexAlign 仓库，不必为此新增第三仓库。[npm pack](https://docs.npmjs.com/cli/v11/commands/npm-pack/)、[包文件 URL 依赖](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#urls-as-dependencies)

不建议让 Aarre 的源码到处直接跨目录导入 NexAlign 的业务文件。把依赖限制在一个独立包入口后，目录变动、类型检查、测试、版本与发布都更容易控制。也不建议把整个 NexAlign 应用作为 Git 依赖安装；当前根包还包含完整应用的构建及依赖，远大于侧栏组件需要的范围。

## 改动范围与验收

这项调整需要收拢共享模块和残留外壳样式、建立包入口/类型/版本、修改两边导入和构建、增加统一构建入口。无需重做两个产品的功能或目前的握手协议。

实施后必须验证：只安装 Aarre、只安装 NexAlign、双安装、旧版混装、卸载/重载恢复、主题同步、拖动位置、菜单开合、收藏动作及网页检查。样式变化仍需生成两份安装包；不能假定所有用户都会同时更新两个插件。混装旧版时应保证各自可用，并保持协议兼容。

推荐下一步按这个方案实施：**组件源码留在 NexAlign 仓库，Aarre 引用版本化组件包；一处维护，两款插件独立交付。**
