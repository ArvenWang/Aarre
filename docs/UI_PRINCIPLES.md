# Aarre UI 原则

## 0.6.2 的对话工作区与验收修正

- 悬浮菜单只有一个工作区。底部常驻可输入的对话框，上方显示收藏或当前对话；不能再出现“收藏 / AI / 设置”切页，也没有单独的 AI 欢迎页。历史和设置是右上角更多菜单中的辅助窗口。
- 输入草稿、发送状态和停止操作随工作区保持；打开设置、取消设置和往返收藏时不能卸载或清空输入。未连接 AI 服务也显示输入框，发送时引导连接，保留原问题。
- 收藏当前网页放在标题栏的星标图标中；完整收藏库的主题、备份、设置在同一个工具组。不能让辅助操作抢占整行主按钮。
- 搜索、筛选、按钮和标签使用适当的小圆角矩形，不能保留旧胶囊。搜索只能有一层可见外壳。浮球、开关和状态圆点保留各自需要的圆形几何。
- 字段标签独占一行。控件值垂直居中，箭头右侧至少 12px 留白。设置以 16px 内容边距和统一分组间距组织，不能重复叠加内边距。
- 选中态通过颜色表达，不使用粗描边。键盘焦点保留细 1px 提示；不能以去掉所有焦点提示来掩盖问题。开关在深色主题下也必须使用亮色圆点。
- 删除确认先放完整说明，再在下一行右对齐取消和确认。长回答、表格和代码限制在所属消息宽度内；滚动不移动底部输入框。
- 验收页先展示本次最新画面和可复查的交互结果。历史截图单独折叠并标记版本；不能把修复前的图和交付图混在同一视觉分组。用户指出的问题按编号逐项关联当前截图与验证结果。

## 0.6.1 的滚动与控件细节

- 所有可滚动区域统一使用 `ScrollSurface`、`ScrollArea` 或共享 `FloatingScrollbars`，包括菜单、下拉列表、弹层、长备注、Markdown 表格/代码、完整收藏库和隐私页。不能只隐藏原生滚动条而不给替代，也不能另写第二套拖动逻辑。
- 滚动条悬浮在内容上方，不占布局宽度，没有底轨。可见细条 5px、透明命中区 12px、首尾至少 6px 留白；短内容不显示。滚动、靠近边缘和键盘聚焦时显示；约 850ms 闲置后以 160ms 过渡淡出；拖动和键盘聚焦时保持可见。文本框的缩放柄与双轴交点要留空间。
- 下拉箭头距边框内侧 12px；触发器文字、箭头、选项选中标记都以正常布局排列，不靠绝对定位叠在文字上。弹出列表跟随触发器宽度，并受当前窗口高度约束。
- 常规控件高 32–40px，字号 13–14px；紧凑菜单的辅助文字最低 12px。选中值不得从组件库意外继承更大的字号。图标、文字与四周留白一起量测，不以单独放大容器解决拥挤。
- 主题和密度必须覆盖 Portal 弹层；自定义组件外壳不能叠加两次内边距。长标题可省略，长内容在所属区域内滚动，不能撑宽整个菜单。
- 横向参照 NexAlign 的细节标准：细滚动条、无轨道、闲置渐隐、适当的字段留白和统一的紧凑字号。保留 Aarre 的信息结构和 HeroUI 组件体系。
- 验收必须包含实际画面：明暗主题、320/400/560px 菜单、完整收藏库、长备注、长回答和双轴滚动；实际拖动、键盘和渐隐过程另留证据。截图逐张检查后才能登记通过。
- Tabs 等集合组件的发现阶段可能重复执行子组件。带状态的全局 Portal 必须放在集合之外；直接入口、关闭和重开后都应只有一个真实弹层。

## 0.6.0 的组件与界面验收

- 业务界面统一使用 HeroUI 3.2.4 和共享适配组件。Tab、Select、Switch、Checkbox、Tooltip、Modal 的键盘与焦点行为由组件库负责。
- 唯一轻量宿主例外：网页中的 52px 原生语义球、大小手柄和隔离 iframe。它们不加载 React；展开后才加载真实业务 UI。宿主的隔离样式允许明确的几何及品牌色常量，且必须与主题一起做视觉回归。
- 菜单为不透明表面，常规 400×600px；窄窗口球独占底部一行，菜单内部滚动。编辑器的正文与底部操作区分开，确认层的 Escape 不得关掉整个编辑器。
- 每次主要 UI 变更都要记录实际浏览器截图、逐图审核、明暗主题对比度和键盘路径。编译、源码断言或截图存在本身不能代表视觉通过。
- 正式扩展包不包含 DEV 数据替身。DEV 截图只证明界面与交互，Chrome 安装态、原生数据和外部服务另列证据。

## 文案

1. 每个控件最多一行说明，且只在"不说会出错"时才写。
   可以写：隐私边界、不可逆操作、涉及成本的估算。
   不要写：功能怎么用、产品怎么工作、鼓励性描述。
2. 空状态只有一行。格式：`还没有 XXX`。不加第二行解释。
3. 不出现"Aarre 会…""我们会…"这类产品自述。
4. 能显示数字就不要用形容词。写 `12/48`，不写"正在处理中"。
5. 错误信息说清楚"发生了什么"和"接下来会怎样"，不说"请稍后重试"。

## 布局

6. 一个页面最多一个主按钮（`variant="primary"`），其余用 ghost 或文字链接。
7. 破坏性操作用文字链接，不用按钮，且必须与主操作分开放置。
8. 详细信息默认收起。日常界面只显示状态，不显示细节。
9. 分区之间只用间距区分，不加分隔线。整页最多一条分隔线。

## 组件

10. 只使用 `@/ui/components/ui/` 下的组件，禁止手写按钮/输入框。
11. 禁止 `variant="unstyled"` + legacy CSS 类的双轨写法。
12. 所有颜色、间距、字号、圆角必须用 `tokens.css` 的变量。

## 检查

违反 10–12 会被 `npm run check:design` 拦截。
违反 1–9 靠 review，新增文案时请对照本文件。

减少动态效果属于明确的可访问性覆盖：仅在 `prefers-reduced-motion: reduce` 内，对固定的 scroll/animation/transition 属性允许 `!important`，用于覆盖第三方控件过渡。设计检查仍禁止其他位置使用；实际控件已量测为 0.01ms。
