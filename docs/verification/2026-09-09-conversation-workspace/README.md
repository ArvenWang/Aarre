# Aarre 0.6.2 · 根据 14 条批注重做对话工作区

上一轮将 NexAlign 的导航结构照搬到了 Aarre，且把修复前的图和交付图放在了相邻位置，导致结构和视觉验收都不够可靠。这一轮以用户批注为准：一个工作区，底部常驻输入框；对话直接在菜单中展开，设置与历史是辅助窗口。当前进展统一记录在根目录 `AGENT_PROGRESS.md`。

[打开最新图集](index.html)。图集默认先展示当前版本，旧版本只保留独立的折叠链接。所有图片均来自实际运行的产品组件，使用隔离的 DEV 收藏和明确标记的 QA 会话；这些数据没有写入用户的 Chrome，也没有发给真实 AI 服务。

## 连贯对话与额外发现

- 未配置服务仍可输入。发送只打开真实设置，问题保留；取消设置后回到同一个输入元素，不丢草稿，也不偷偷发送。
- 从收藏直接发送、返回收藏、继续追问、停止、打开历史和新建会话均通过真实组件回放。继续追问携带 2 条前文；停止后迟到的结果不会覆盖取消状态。
- 新增 4 个根应用集成回归，验证上述草稿/发送/停止路径，以及完成前的流式文本显示。现有流客户端的断连、空闲超时、总超时和完成后断连测试继续保留。
- 发现并修复原有流式呈现缺陷：消息处于发送状态时总是画“思考中”，即使已经收到部分内容。现在首段即可显示，后续段落增量更新；完成后移除端口监听并恢复输入。`streaming-flow.json` 中同一个 composer 始终保留，完成后监听数为 0。
- 真实宿主回放额外发现慢加载恢复缺陷：15 秒超时后若界面才发出就绪消息，旧的重试标志不会被清掉，下次展开会重建 iframe。现在合法就绪消息同时清除重试状态；2 个宿主集成用例验证恢复后保留 iframe、真正失败仍可重试、旧 iframe 迟到消息被忽略。修复前后结果保留在 `logs/host-recovery-before.txt` 与 `logs/host-recovery-after.txt`。
- 问题编辑改为旁侧图标，不再为隐藏的文字按钮占用整行；单条 AI 提案直接显示具体操作名称，并提供明晰的展开箭头。
- 21 条 QA 历史记录的列表宽/滚动宽均为 294px，正文在 558px 高区域内滚动；20 行草稿的输入区域上限 112px，底部发送区保持在 628px。见 `history-and-composer.json`。

## 视觉与交互证据

- `final/` 共 61 张本轮当前画面，`visual-review.json` 记录逐张图像审核与 SHA-256。截图存在本身不代表通过，必须查看实际画面。
- `gallery-check.json`：实际打开本地文件图集，1150px 与 420px 下 61/61 图片加载成功，没有横向溢出。补充图默认折叠；旧页默认只显示更新提示及指向本轮的入口。图集本身另有两张实景截图在 `logs/`，不计入 61 张产品画面。
- `menu-geometry.json`：17 组菜单/设置/下拉/编辑/确认场景，没有页面横溢出；所有实际可滚动区域均有共享自制滚动条。
- `manager-geometry.json`：21 组完整收藏库及辅助窗口场景，没有页面横溢出或缺失自制滚动条。
- `conversation-flow.json`：真实发送入口与会话状态流程；正文 320/400/560px 均不横溢出。400px 时表格/代码容器宽 368px，内容分别宽 708px 和 1108px，范围被限制在块内。
- `streaming-flow.json`：通过受控本地 Port 向正式流客户端发送增量与完成事件；没有向外部服务发请求，也没有执行展示的 QA 提案。
- `scroll-drag.json`：真实鼠标拖动使偏移 280→552px；细条 5px、命中区 12px、底轨透明，内容宽度保持 400px。闲置渐隐的实际过渡为 160ms，中间 40ms 帧透明度 0.39278，结束为 0；静止截图对应位置的像素已复核为背景色。
- `theme-image-check.json`：通过实际主题按钮操作并等待可见图片解码。程序切换主题后的早期截图出现封面未完整绘制，保留一张在 `logs/`，不计入最终审核；不能把这种早期图当成稳定画面。
- `host-runtime.json`：实际宿主在 1280×900px 明暗主题、420×760px 窄窗均留在可见区域，iframe 内容宽等于滚动宽；输入框在 frame 底部留出 12px。关闭/重开保留同一 iframe、同一 composer 和中文草稿，焦点返回输入框；原网页宽度保持 1265px。
- `capture-*.mjs` 均使用 Ego Browser。脚本中的本机路径和任务空间 8 属于此次环境；复用时需调整到自己的任务空间。正式扩展不包含这些 DEV 替身。

## 交付验证

完整检查、正式封装和独立哈希校验在源代码及当前视觉证据收尾后执行，最终结果统一补记在本节和根 `AGENT_PROGRESS.md`。0.6.1 已封装产物不覆盖，0.6.2 单独交付。

实际 Chrome 安装态、真实 Provider、原生书签写操作与云端服务是独立验收边界。后台本轮未部署；没有推送、合并或商店发布。电脑端验证请从 0.6.2 解压目录更新扩展并刷新普通网页。

组件继续采用项目已固定的 HeroUI 3.2.4，没有为改造样式再引入第二套组件库。复核依据包括 [HeroUI Dropdown 官方结构](https://heroui.com/en/docs/react/migration/dropdown) 与 [Input 官方说明](https://heroui.com/en/docs/react/components/input)，具体样式以项目的共享适配层和真实浏览器量测为准。
