## 实际发现与修复

首轮真实 Chrome 重载仍显示旧错误。只读检查确认同一验收页存在两个宿主：新版连接正常，但旧版 MutationObserver 把被移除的旧入口重新挂回了网页。旧扩展环境的 window 全局无法由新环境直接清理。

现在通过宿主 DOM 上的退役事件清理旧观察器和监听；对没有该协议的 0.6.7 及更早宿主，将其隐藏、设为 inert、移出顶层并保留连接状态，避免旧观察器复挂。兼容节点随原网页自然关闭或导航回收，不刷新网页，也不改动页面输入。后续版本正常清理旧节点。健康连接保留原 iframe 和草稿。

保存目标在连接验证之后、React 首次渲染之前传入；父层遮罩直到表单已挂载才撤下。加载、就绪和表单提交分开，加载失败有15秒上限与重新打开入口。关闭时不会先将紧凑表单拉大为首页。存在其他未完成编辑或任务时保留原操作并给出提示，避免把它困在加载遮罩后。

## 浏览器边界

自动入口适用于获得网站权限的HTTP(S)普通网页。Chrome内置页、商店及浏览器禁止注入的文档不能由扩展强制插入按钮，点击扩展图标时仍由完整收藏库承接。用户主动关闭入口或隐藏某站点的选择继续生效。

实现依据：Chrome 官方 [内容脚本与注入方式](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting)。升级后旧观察器复挂的判断来自本机实际复现和只读诊断，不是仅凭文档推断。
