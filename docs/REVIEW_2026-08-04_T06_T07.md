## 一、通过项（已验证，附证据）

### 1. MV3 事件注册时机正确 ✅

这是 Service Worker 拆分最容易出事的地方：监听器若在 `await` 之后注册，SW 休眠唤醒后事件会静默丢失，而且开发时发现不了（开发中 SW 一直活着）。

实测结论：

- `background.ts` 只有 3 行，顶层同步调用 `initializeBackground()`。
- `initializeBackground(): void` 是**同步函数**，函数体内无顶层 `await`。
- 所有注册入口 `registerPageEvents` / `registerBookmarkEvents` / `registerUiEvents` / `registerInstallLifecycle` 均为同步 `export function`，其中的 `addListener` 都在同步路径上。
- 唯二的异步调用是 `void configureActionSidePanelBehavior().catch(...)` 和 `runBackgroundStartupMaintenance()`，都用 `void` 抛出，不阻塞注册。

监听器回调本身是 `async` 没有问题——要求的是**注册动作**同步，不是回调同步。

实测：`Test Files 2 failed | 60 passed (62)`，`Tests 3 failed | 363 passed (366)`。

进展文档写的"366 项全绿"应当是拆分中途某个时点的真实状态，之后又搬了一批代码，测试没跟着改。这属于 T-07 进行中的正常情况，但请把进展文档里的结论改成阶段性表述，不要写成已全绿——下一个 agent 会据此跳过验证。

### P1｜4 条守卫已永真失效，且是绿灯 🔴（比上一条更危险）

`tests/surface-coexistence.test.ts:13-16`：

```js
const source = await readFile(new URL("../src/extension/background.ts", ...));
expect(source).not.toContain("chrome.action.onClicked.addListener");
expect(source).not.toContain("chrome.sidePanel.close");
expect(source).not.toContain("closeManagerTabs");
expect(source).not.toContain("coordinateManagerTabSidePanel");
```

`background.ts` 现在只有 3 行。**这四条断言现在永远成立，守卫已经完全失效，但测试是绿的。**

它们原本防的是"侧边栏与网页端互相关闭"这个已修复的回归。现在如果有人在 `bootstrap.ts`、`lifecycle/` 或 `coordinators/` 里引入 `chrome.sidePanel.close`，测试不会有任何反应。

已确认这四个符号目前在整个代码库中都不存在，即**当前行为仍然正确**，失效的是防线而不是功能。

**这里有一个值得记住的对称性：** 同一个搬迁动作，对 `toContain` 断言表现为红灯（会被发现，就是上面那 3 条），对 `not.toContain` 断言表现为绿灯（不会被发现）。所以修的时候**不能只修红的**——必须同时把所有 `not.toContain` 类守卫的扫描范围一起扩大，否则会留下一批看不见的空壳测试。

**修法：** 把这类守卫从"读单个文件"改为"扫描整个目录"。建议加一个共用助手：

```ts
async function readAllSources(dir: URL): Promise<string> {
  // 递归读取 dir 下所有 .ts/.tsx，拼成一个字符串再做 not.toContain
}
```

然后 `expect(await readAllSources(extensionDir)).not.toContain("chrome.sidePanel.close")`。这样无论代码搬到哪个文件，守卫都有效。

**建议顺手做一次全库排查**：所有 `not.toContain` 的源码守卫都要确认它读的文件仍然是被约束代码的真实所在地。

`tests/sidepanel-layout-stability.test.ts` 中，这条断言原先读 `SidePanelApp.tsx`，用于验证"侧边栏确实挂载了思考步骤组件"。改为读 `components/AgentThinkingSteps.tsx` 后，等于在组件自己的文件里断言它自己的名字——几乎永真，失去了原本的校验意义。
