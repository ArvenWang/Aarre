# Aarre 悬浮交互升级与质量整改计划

制定日期：2026-09-09。状态：**M01～M07 已实施，M08 本地验收完成；安装态与外部服务验收仍开放**。

本计划落实用户的新要求：以 NexAlign 的悬浮球和菜单为形态参考，升级 Aarre 的主要入口，统一使用成熟组件库，并处理本轮稳定性、体验和视觉审计发现。执行状态在根 [AGENT_PROGRESS.md](../AGENT_PROGRESS.md) 维护；本文件是实施规格与验收依据。[逐项验收结果、36 张实际截图与未通过边界](verification/2026-09-09/README.md) 已交付。

## 1. 建议确定的方案

**采用「悬浮球 + 浮动菜单 + 完整收藏库」，以 HeroUI 3 统一界面系统。**

- **悬浮球**：浏览网页时的轻量入口，可拖动、收起、按站点隐藏。
- **浮动菜单**：完成当前页收藏、查找收藏、AI 对话和日常设置。
- **完整收藏库**：继续使用独立扩展页面，承载批量整理、报告、主题图谱、重新发现和备份恢复。管理页自己的查询和筛选条件通过 URL 保留。
- **稳定性整改**：与形态升级一起纳入交付，优先解决数据遗漏、旧数据覆盖新数据、错误状态不可信的问题。

菜单负责高频操作，收藏库负责需要大面积内容或多项选择的操作。两者使用同一套组件、数据服务和操作规则。

## 2. 组件库选择：HeroUI 3

| 候选 | 适合本项目的部分 | 本次判断 |
| --- | --- | --- |
| **HeroUI 3** | 适配现有 React 19 / Tailwind 4；提供表单、菜单、对话框、反馈、表格等组件；NexAlign 已有接入经验 | **选用**。能够统一两个项目的组件经验，减少各页面重复维护交互 |
| Mantine | 组件、表单、通知等覆盖广，有正式 Vite 接入方式 | 能完成任务；但需要另建 Mantine 主题和组件适配，当前没有足以抵消迁移成本的 Aarre 专属收益 |
| shadcn/ui + Base UI / Radix | 与当前依赖较接近，可直接拥有和修改组件代码 | 也是可行方案；更偏向维护自己的组件集合。本次优先让成熟库承担基础控件的长期维护 |

这是结合仓库的选型判断，不代表组件库的通用排名。官方依据：[HeroUI 接入要求](https://heroui.com/en/docs/react/getting-started/quick-start)、[HeroUI 组件目录](https://heroui.com/en/docs/react/components)、[Mantine 接入与包组成](https://mantine.dev/getting-started/)、[shadcn/ui 的代码分发模式](https://ui.shadcn.com/docs)。

### 组件使用规则

继续以 `src/ui/components/ui/` 为唯一业务组件入口，底层接入真正的 HeroUI 组件。包装层只统一命名、尺寸、主题和业务需要的属性；复合控件保留库要求的结构与交互语义。

| 界面需求 | 优先采用的 HeroUI 组件 | Aarre 需要保留的业务部分 |
| --- | --- | --- |
| 主次操作、图标操作 | Button、CloseButton、ButtonGroup、Tooltip、Kbd | 真实 pending / disabled 状态、快捷键说明 |
| 搜索与表单 | SearchField、TextField、Input、TextArea、Form、FieldError | 收藏标题、网址校验、备注、Provider 配置 |
| 文件夹选择、标签 | Select、ComboBox、ListBox、TagGroup | Chrome 文件夹身份、标签增删规则 |
| 开关与多选 | Switch、Checkbox、RadioGroup | 现有设置存储、隐私保护、批量选择 |
| 导航和更多操作 | Tabs、Dropdown、Menu、Popover | 收藏 / AI / 设置路由与操作权限 |
| 编辑与确认 | Modal、AlertDialog、Drawer | 保存、删除、导入冲突、返回草稿规则 |
| 状态反馈 | Toast、Alert、ProgressBar、Spinner、Skeleton、EmptyState | 来源于真实任务状态的进度、错误与恢复入口 |
| 收藏库与设置结构 | Card、Surface、Accordion、Separator、Table、Pagination | 收藏卡片内容、报告数据、历史记录分页 |

以上主要组件已核对 NexAlign 安装的 HeroUI 3.2.4 导出目录。树形收藏、卡片瀑布流和 Canvas 图谱是业务呈现，不能靠换一个通用控件自动完成；保留业务组件，用统一控件承载操作，并补齐键盘和列表入口。HeroUI 没有完整覆盖的树形交互，实施时优先评估同一 React Aria 体系的能力，再决定是否适配现有树。

具体约束：

1. 所有已有 UI 页面都进入迁移清单，包括浮动菜单、收藏库、编辑器、设置、AI、引导、隐私页和确认流程。基础控件有对应组件的，全部接入；迁移完成后清除失去用途的旧依赖和样式。
2. 用主题 token 定制 Aarre 风格，保留库的焦点、禁用、校验、选择和弹层行为。避免清空组件默认样式后重新手写一套。
3. 优先按公开子路径引入，并核对构建图；不通过依赖包内部文件路径绕开 API，也不把 UI 库带进 Service Worker。
4. 明确 `onPress` / `onClick`、受控值和 pending 状态的适配，验证每次点击只提交一次。NexAlign 的项目专用事件补丁需要单独评估，不能直接照搬。
5. 所有弹层留在扩展 iframe 的文档内，统一层级与焦点恢复；正文滚动不带动固定操作区。
6. **轻量悬浮宿主是有理由的例外**：页面中只有原生语义按钮、拖动壳和 iframe 容器，复用生成的 token；React 与 HeroUI 在用户展开后加载。将这个有限例外写入 `UI_PRINCIPLES.md`，其余业务控件仍走共享组件。
7. 本计划依赖开源核心组件，不要求购买 HeroUI Pro。

## 3. 新界面怎样使用

### 3.1 默认行为与视觉规格

以下是本轮确定的实施默认值，尺寸是设计起点，需在真实页面验收后微调。

| 项目 | 规格 |
| --- | --- |
| 常驻策略 | 完成首次引导后，在允许注入的普通网页默认显示收起的球；升级用户首次使用时展示一次简短迁移提示。提供「在此网站隐藏」和全局显示开关 |
| 唤起 | 点击球、扩展图标或现有 `Alt+Shift+B` 展开；收起态不会自动弹出菜单或抢焦点 |
| 悬浮球 | 52×52px、Aarre 自有标识、日夜主题、明确 focus ring；默认右下，距可见视口边缘 12px |
| 拖动 | 超过 6px 位移才判为拖动，拖动结束不误触展开；支持靠边停靠、记忆位置和「重置位置」 |
| 菜单 | 桌面起始宽 400px、高 600px，距球 12px；空间不足时向另一侧展开并约束高度，不推挤网页布局 |
| 尺寸调整 | 允许拖动手柄调整尺寸；宽度常规约束 320～560px，高度受可见视口约束。窄窗优先使用 `视口宽度 - 24px`，覆盖常规最小宽限制 |
| 窄窗 | 在 360/420px 桌面窗口内保证字段、导航和操作完整；高度不足时内部滚动，并保留「打开收藏库」入口。这不等于提供手机 Chrome 扩展 |
| 表面 | 不透明的中性浅色/深色 surface，清楚边界、适度阴影；保留 Aarre 的手绘分类封面与内容卡片风格 |
| 排版 | 正文以 14px 为起点，辅助信息 12～13px；中文长标题可读。信息文字对比度至少 4.5:1，不用过淡的小字承担关键说明 |
| 控件 | 常规点击高度 36～40px；小图标有足够点击范围、可见焦点和可读名称 |
| 动效 | 球与菜单展开/收起约 160～220ms；尊重减少动态效果设置；不使用持续呼吸或装饰性旋转 |

球默认使用 Aarre 品牌标识，已收藏状态在菜单的当前页面区明确呈现。需要处理的任务失败可以显示一个低干扰标记；正常后台工作不让球持续闪动，也不让颜色单独承担状态说明。

球的位置和尺寸保存在当前浏览器配置中；站点隐藏设置按明确站点范围保存。不同电脑不同步绝对坐标。关闭全局显示后，扩展图标仍可在当前页面临时唤起菜单，并可进入设置重新开启常驻。

### 3.2 菜单信息结构

菜单头部显示 Aarre 标识、「打开完整收藏库」和更多操作；球展开后变为收起按钮。内部使用三个固定标签：**收藏、AI、设置**。

| 区域 | 内容和主要动作 | 路由与持久状态 |
| --- | --- | --- |
| 收藏 | 当前页面标题与收藏状态；收藏/编辑；搜索；原生文件夹树和搜索结果；必要的真实状态反馈 | 搜索词、文件夹、筛选条件 |
| AI | 对话、收藏来源、停止生成、重试、历史会话；基于现有真实 Agent 和执行确认流程 | 会话身份、来源、待确认动作 |
| 设置 | 外观与球位置、AI 服务、账号与完整同步；最近更改及数据管理入口 | 对应设置或恢复页面 |
| 收藏库 | 收藏库、整理提案、报告、主题图谱、重新发现 | 各页面已有路由与筛选状态 |

收藏页搜索和当前页操作置顶；AI 输入区、编辑保存区固定在各自容器底部；正文独立滚动。复杂设置进入菜单内二级页面，数据恢复和大规模整理进入完整收藏库的专用页面。

### 3.3 从旧入口到新入口

| 现有入口/功能 | 新行为 | 必须保留的行为 |
| --- | --- | --- |
| 扩展图标、快捷键 | 展开/收起当前网页的浮动菜单 | 多窗口目标准确，错误可见 |
| Chrome 原生星标收藏 | 原生收藏照常完成；球/轻提示反映真实保存及增强状态 | 不重复创建、不擅自弹出编辑表单、不干扰 Chrome 原生弹窗 |
| 右键收藏当前页 | 在对应页面打开浮动编辑器 | 使用右键事件里的目标 tab 和页面，不用稍后查询的活动页替代 |
| 右键收藏链接 | 编辑器明确显示被点击的链接及标题 | 链接目标与宿主页区分，不能给链接套用宿主页面截图 |
| 右键刷新截图/使用图片封面 | 在当前授权目标上执行并反馈 | 现有保护过滤、封面来源与失败处理 |
| 收藏搜索、拼音搜索、文件夹操作 | 在收藏标签继续可用 | 多收藏位置、打开方式、重命名、移动、删除与撤销语义 |
| 编辑收藏/新增文件夹 | 菜单内同一套编辑组件；大窗也使用它 | 保存前校验，清空字段能同步，操作按钮始终可达 |
| AI 与历史会话 | AI 标签及历史入口 | 真实来源胶囊、计划预览、执行确认、停止与中断恢复 |
| 云同步、最近更改、数据导出 | 设置入口及完整数据管理页面 | 完整备份范围、真实状态、30 天保留规则 |
| 旧侧栏深链和内部消息 | 过渡期间统一重定向到新打开入口 | 更新右键、快捷键、引导与设置中的全部调用点 |
| 不能注入的页面/已撤回站点访问权限 | 扩展图标打开完整收藏库，携带可用的原始目标上下文并说明限制 | 可以继续搜索和整理；需要读取页面的操作明确不可用 |

原生侧栏在迁移阶段仅作为内部回归对照。最终移除它作为产品入口的配置、过时打开逻辑和确认无用途的权限；用户看到的是一套新入口系统。

### 3.4 关闭、焦点和多标签页合同

- 普通菜单是非模态工具，不遮住网页其他区域，也不在初次注入时夺取网页焦点。点击球/快捷键打开后，将焦点放到合适的首个控件；关闭后还给触发元素或原网页位置。
- 点击菜单外区域收起普通菜单；编辑草稿先保存到本地。表单校验或确认弹层打开时，先由最上层弹层处理关闭，不让外层提前卸载。
- `Escape` 依次关闭下拉/提示层、编辑或确认层、最后收起菜单；中文输入法正在组词时不拦截 Escape/Enter。收起状态的 iframe 必须不可聚焦、不可点击。
- 单击展开与拖动互斥；提供键盘移动/重置位置的路径。展开菜单滚动到边界后不把滚轮意外传给网页。
- **每个页面实例绑定来源标签与文档身份。** 切到标签 B 时，A 中的草稿和待执行动作仍属于 A；B 的收藏状态按 B 计算。旧页面跳转后，旧响应不能改写新页内容。
- 收藏库是独立浏览场所；其「收藏当前页」类操作使用明确传入的来源，来源失效时让用户重新选择，不能默默收藏收藏库自身。
- 同一页面收起/展开保留搜索、滚动、草稿与会话。导航/重载后，草稿和会话可从本地持久状态恢复；后台任务只报告已经落库的结果。
- AI 任务若仍在后台执行，重新打开后恢复同一任务状态；若已中断，显示保留的内容和明确重试入口，不自动重复执行写入动作。

## 4. 实现结构与新增风险处理

### 4.1 采用隔离宿主 + 扩展页面

网页中注入一个轻量宿主，用关闭的 Shadow DOM 隔离样式，使用顶层弹出层承载球和菜单位置；完整 React / HeroUI 菜单运行在 `chrome-extension://…/floating.html` 的 iframe 内。收藏库与菜单共用业务模块。

这对 Aarre 尤其重要：其现有代码会直接访问 IndexedDB 等存储。Chrome 官方说明，content script 中的 Web Storage 属于宿主网页；扩展来源内的存储则共享，嵌入网页的扩展 iframe 也保有扩展自身的存储分区。因此业务不能直接搬进网页的 React 根节点。[Chrome 存储说明](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)

宿主只负责显示、位置、生命周期和有限交互信号；收藏读写、账号与 AI 权限继续由扩展服务处理。content script 可直接使用的扩展 API 有限制，需要通过消息访问其他能力。[Chrome content script 说明](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)

### 4.2 必须在基础阶段解决的边界

| 风险 | 处理要求 | 通过标准 |
| --- | --- | --- |
| 网页冒充菜单发送消息 | 后台依据浏览器提供的 sender、tab、frame/document 建立宿主会话；校验扩展来源、父文档关系、generation 和能力范围 | 伪造来源、过期会话、其他标签、未登记 iframe 的业务请求均被拒绝 |
| 把 Shadow DOM 当作安全边界 | Shadow DOM 仅隔离样式；页面消息视为不可信，限制宿主操作集合，凭证和整库内容不发给网页宿主 | 页面可见 DOM、日志、宿主通信不含账号令牌、API Key 或整库数据 |
| 扩展资源暴露扩大 | 仅开放浮动入口和确实需要由网页访问的资源；构建生成可审查的清单；业务 chunk 在扩展来源内加载 | 无 `resources: ["*"]`；任意站点直接嵌入入口时，未经宿主验证不能显示业务内容 |
| CSP / 页面弹层 / 站点 CSS 影响 | 在真实页面验证 iframe 加载、顶层顺序、transform、zoom、全屏和已有弹窗；失败时给出可用收藏库入口 | 不白屏、不阻断网页点击、不反复抢占网站弹窗 |
| 网页导航、BFCache、SPA | 每个顶层文档仅一个宿主；处理旧文档失效、同文档 URL 变化、前进后退、扩展重载和权限撤回 | 无重复球、残留监听、错页状态和不可收起菜单 |
| 背景任务/连接中断 | 连接断开和超时都有最终状态；未完成动作有持久身份；需要用户确认的写入不会因重连重复执行 | 关闭菜单/切页/重启 Worker 后状态可解释、可恢复 |
| 弹层被 iframe 边界裁切 | 菜单内弹层向内定位；编辑用内部 Modal/Drawer；大的预览在菜单内或打开收藏库 | 下拉尾项、确认按钮、长内容均可见可达 |
| 原网页滚动/焦点被破坏 | 宿主空白区域不拦截指针，不修改网页布局；关闭时移除焦点与滚动限制 | 常规网页输入、快捷键、滚动与选中仍能工作 |

通信规则依据 [Chrome 消息安全说明](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)；资源开放范围依据 [Web Accessible Resources 说明](https://developer.chrome.com/docs/extensions/reference/manifest/web-accessible-resources)。这些规范支持架构选择，不代替 Aarre 真实安装态测试。

### 4.3 截图前隐藏整个工具

现有截图有可见标签截图与 debugger 批量截图两条路径，都必须接入同一套「隐藏—确认—截图—恢复」流程。

1. 确定目标 tab、文档和截图任务，沿用现有前台状态及隐私检查。
2. 向该文档发送带任务身份的隐藏请求；隐藏球、菜单、预览和 Aarre 提示，并等待渲染后确认。
3. 确认目标页面仍未变化，再执行截图；如果未能可靠隐藏，保留原封面并给出可重试状态。
4. 成功、失败、超时、取消都通过 `finally` 恢复；宿主另有超时恢复机制，防止 Worker 退出后工具永久消失。
5. 并发任务使用引用计数或明确租约，防止一个任务过早恢复另一个任务仍需隐藏的 UI。

验收既检查业务结果，也检查生成的真实图片：封面不包含球、菜单、提示条；隐藏期间不丢草稿、不取消正常对话、不让自身文案进入 AI 页面提取。

## 5. 分八批实施

编号 M01～M08 专用于本计划；历史已完成任务不重开。每批都交付真实业务改动、针对性验证及进展更新；“该批完成”不等于整版可发布。

### M01 · 恢复可靠的验证基础，处理依赖风险

**解决：A12、A13、A14、A15。**

- 修复现有预览的 Chrome 事件适配；新浮动 UI 接同一接口适配层。开发数据明确标为 fixture，无法接入真实扩展时明确报错。
- 撤销测试固定时钟并覆盖有效期边界，保留真实 30 天规则。
- UI 审计必须声明场景清单、成功/失败/阻塞数量；缺失必测页面和初始化失败导致非零退出。
- 依次处理当前根目录 5 项、服务端 3 项依赖公告；未使用的高风险依赖先核实后移除，有用途的升级并验证实际调用路径。HeroUI 引入后重新核对锁文件与公告。
- 将本轮 10 个独立故障用例转换为适当的正式回归测试，保持原审计证据不变。

**交付/验收：** 标准检查不存在日期造成的失败；故意制造页面启动错误时审计确实失败；依赖结论有明确版本和影响路径。M02/M03 的测试随着相应修复转绿，不能删断言或更改预期掩盖缺陷。

### M02 · 保证同步后的数据正确

**解决：A01、A02、A05、A06、A10。依赖：M01 的故障基线。**

- **A01：** 一页变化、本地资源和游标在同一 IndexedDB 提交边界内落盘；重试按稳定操作身份幂等执行。跨存储游标需迁到同一事务，不能仅调整两行代码次序。
- **A02：** 按服务端变化顺序应用更新和删除；后到的删除不会被提前缓存的旧更新写回，保留 tombstone 与旧客户端兼容性验证。
- **A05：** 上传携带本地 revision；响应只能确认它对应的版本，不能覆盖请求发出后新写的备注和标签。新修改持续保留在待上传队列。
- **A06：** 分离本地图片内容版本、待上传标记与远端版本；旧字节不能仅因为 hash 不同就取得覆盖权。必要时服务端增加条件写入/冲突响应，并验证拉取图片后的真实内容。
- **A10：** 约定 `缺省=未修改`、`空字符串/空数组或明确删除值=用户清空`，客户端、字段时钟、服务端 schema 和合并规则一致。

**交付/验收：** 两个独立客户端在断网、第二页拉取失败、更新后删除、同时修改、清空字段和封面竞争后，最终得到相同的预期数据；新旧客户端过渡不丢字段。真实 PostgreSQL 测试与真实对象存储验收分别记录。

### M03 · 让故障可见，也能恢复

**解决：A03、A04、A07、A08、A09。依赖：M02 的提交语义。**

- 同步状态区分正在同步、仍有项目失败、等待网络、需要重新登录和已同步；只有对应队列确实完成时才更新成功时间。
- 「立即同步」可以越过本地退避重新发起一次请求；尊重服务端限流的明确等待时间，防止重复点击并发提交。
- 网络超时、5xx 等临时问题保留会话；明确失效才退出登录。覆盖刷新令牌轮换中“服务端成功、客户端没收到响应”的恢复路径。
- Agent 增加断连、超时、停止和重连处理；保存已收到内容；写入动作的重试以 operationId 去重。
- 最近更改使用分页/加载更多，保留期内所有条目可达；到期说明和撤销失败原因明确。

**交付/验收：** 上传部分失败不能显示已同步；手动重试有可观察请求或明确等待原因；离线不清掉有效账号；AI 断线能够结束等待并保留内容；第 13 条及更早的有效记录能找回。

### M04 · 建立 HeroUI 和 Aarre 视觉基础

**解决：A16，并建立整套 UI 迁移标准。依赖：M01。**

- 迁移基础按钮、输入、标签、Tab、弹层、确认、错误和进度组件；为 pending、disabled、invalid、selected、focus 等状态建立实际组件验收页。
- 用真实收藏编辑器、搜索结果和 AI 输入区校验组件组合，覆盖日夜主题、长中文标题、输入法与窄窗口。
- 明确界面尺寸及滚动合同；去掉低对比辅助文字和会因 hover 导致布局晃动的处理。
- 扩展组件使用检查，记录合理的宿主例外，阻止新增普通手写控件和重复视觉系统。

**交付/验收：** 共用控件真实来自 HeroUI；正文与辅助信息可读；键盘顺序、表单错误、一次点击一次提交均通过。组件验收页仅为开发验证资料，不能充当用户产品功能。

### 性能门槛

现有 `background.js` 为 **329,976 bytes**，距离现有 330,000-byte 门禁仅 24 bytes。新增悬浮协调逻辑前先优化边界和懒加载，不能简单放宽门槛；UI 库只进入 UI 产物。

- 收起的球不加载完整收藏树、HeroUI 菜单、AI 或报告；仅有轻量宿主，不轮询整页 DOM。
- 一次文档只注入一次；MutationObserver 如确有需要，限制范围并节流；拖动按动画帧更新，空闲时没有持续位置计算。
- 查询、图片解码、目录展开按需执行；大列表采用测量后确认需要的虚拟化/分批加载，不能因虚拟化破坏键盘和搜索结果定位。
- 菜单重复开关、切换 20 个标签和页面导航后，核对监听、iframe、队列与内存是否持续增长。
- 暂定交互预算：固定测试机器上，暖展开与本地搜索结果更新的 p95 不超过 200ms；首次展开 200ms 内有真实加载反馈。M04/M05 先记录设备、样本、冷暖定义和基线，再冻结可重复的门槛；本轮未测得这些目标已达成。
- 截图等待、网络请求和 AI 首字耗时单独统计；加载动画不会算作业务完成。
